# 認知・会話型投稿の追加実験

## 目的と境界

既存の「短い親→子①の解説→子②の希望とLINE相談」を止めずに、ジローをまだ知らない人が反応・会話・プロフィール訪問をしたくなる投稿を加える。毎回「……」で終わる親投稿や「実は、5つあるんです！！」を新型へ流用しない。逆に、既存の3部投稿へ新型を無理に押し込まない。

他アカウントの表示数は発想の資料であり、ジローのアカウントでの再現を保証しない。元投稿の文、画像、動画、人物、LINE通知、実績数値はコピーしない。

## 参考画像から抽出する反応の入口

| 入口 | 参考画像の働き | ジローで試す方向 |
|---|---|---|
| 一言の本音 | 読者が「私も」と言いやすい | 「もう一度、彼と何でもない日曜日を過ごしたい。」のように具体的な願いを短く書く |
| 答えたくなる問い | 自分の経験をコメントしやすい | 「別れた彼から『久しぶり』と来たら、最初に何を返したい？」など |
| 対比・意外な見方 | 一瞬で意味が取れ、賛否が生まれる | 「戻りたいのは、昔の2人にじゃなくて……」など。ただし読者を責めない |
| 生活の一場面 | 抽象的な恋愛論を自分事にする | 一緒にスーパーへ行く、平日の夕食など、読者が望む日常を描く |
| 具体的な画像 | 内容を止めて見てもらう仮説 | 権利を確認した本人素材か、オリジナルの情景写真・文字画像を添える |

最初のテスト候補は、既存5枠を維持するなら3部投稿3枠＋認知・会話型2枠。これは**試験配分案**であり固定比率ではない。朝夜の時間効果と形式効果を混同しないよう、型の時間帯を日ごとに回す。まず一言・問いを各1本試し、次に画像有無を同系統の文章で比較する。別形式の投入が実装・予約に反映されたことを確認するまで、本番に切り替えない。

## 「人が書いている」基準

- ジロー本人の立場から、読者に話しかける・迷いを受け止める・日常の情景を言葉にする。毎回同じ導入、同じ句読点、同じ締め、同じ項目数にしない。
- 文章の長短や問いの有無は意図的に変える。絵文字や口語は内容に合うときだけ使う。ランダムな口調変化は「人間味」ではない。
- コメントを求めるだけの釣り、確実な復縁の断言、彼の心理の決めつけ、別れた相手への接触を煽る表現は避ける。
- 別れが安全・尊厳に関わる場合もあるので、復縁だけを唯一の正解として言わない。

## 画像の扱い

Threads APIは公開URLの画像で画像投稿コンテナを作り、`alt_text` を付けられる（[Meta公式Threads APIコレクション](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api)）。現行のWorkerは `media_type: TEXT` 固定なので、画像投稿には公開画像の保管場所、画像URL、代替テキスト、公開前検証、失敗時の停止処理を追加する必要がある。

著名人の写真・動画、他人の投稿スクリーンショット、第三者のLINE画面を無断転載しない。「彼から連絡が来た」画像、顧客の成功報告、人数などを架空の証拠として作らない。オリジナル素材でも実際の受信画面のように誤認させない。画像が効いたかは同じ文系統のテキストのみとの比較で判断し、引用投稿や外部事例の数値を自分の成果として扱わない。

## 記録と判定

各投稿に目的（認知／会話／相談）、型、テーマ、冒頭語、画像種別、CTA有無、時刻、1h・6h・24h・72h表示数、いいね・返信・再投稿、プロフィール訪問・フォローを記録。取得できない値は空欄にする。

同じ経過時間・近い時刻の自アカウント投稿と比較し、初速と24時間後を分ける。形式や画像の効果を判断するときは他条件をできるだけ揃え、複数回の再現を見る。反応が良い投稿はテーマを変えずに構造だけ残して展開し、弱い型は止める。「たまたま伸びた」可能性を明記する。

ユーザー確認済みの方針：認知・会話型の本文にはLINEリンクを入れない。既存3部投稿の子②は固定LINE CTAを維持する。認知投稿はまず反応・会話・プロフィール訪問を測り、直接相談数だけで評価しない。
