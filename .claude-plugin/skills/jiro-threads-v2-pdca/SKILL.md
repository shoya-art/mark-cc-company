# ジローのThreads投稿とPDCA

現行の親＋子①＋子②は残す。その上で、認知を広げ、いいね・返信・再投稿を生む別の投稿形式を検証する。認知・会話型の本文にはLINEリンクを入れず、3部投稿の子②には固定LINE CTAを残す。実装の正本は `threads-v2/src/content.js` の `RULES`、`DISCOVERY_RULES` と検証関数、予約・計測の正本は `threads-v2/src/worker.js`。ローカルのWorkerは3部投稿3枠＋認知型2枠のテキスト投稿に対応したが、画像投稿と返信数の自動計測は未実装。本番反映は別途確認する。公開や予約の操作は、その都度依頼された範囲で行う。

認知・会話型の設計と画像の扱いは、必要時に [references/discovery-experiments.md](references/discovery-experiments.md) を読む。

## 読者と優先する訴求

将来を考えていた彼と別れ、復縁したいアラサー女性が中心。結婚・出産・年齢の焦りは背景として理解するが、入口でそれを煽らない。最初に届けるのは「彼や2人の関係には、まだ前向きな変化の余地があるかもしれない」という希望。

ユーザーが重視する仮説は、**彼目線で『彼が復縁を考え始める瞬間』を示唆するフックが最も強い**、次に**1度離れた2人が戻る可能性・共通点**。彼の気持ちが時間とともに変わるかもしれない、今すぐ何かしなくても関係を見直す余地があるかもしれない、という淡い期待を入口にする。これは投稿設計上の優先仮説であり、全員の彼の心理や復縁結果についての事実・保証ではない。

使うフックの方向性：

- 「男性が別れた彼女との復縁を考え始める瞬間って……」
- 「別れた彼があなたを思い出す瞬間って……」
- 「復縁したら幸せになれる2人の共通点って……」
- 「1度離れた2人が戻れる共通点って……」
- 「絶対に復縁した方がいい2人の特徴って……」も検証候補。ただし本文では適否を状況別に扱い、「全員が戻れる」「彼は必ずそう思う」と言わない。

親投稿はこの程度の短い疑問のまま「……」で切る。読んだ瞬間に意味がわかり、答えを知りたくなることを優先する。結婚という遠い理想、強すぎる煽り、悲観的な長い導入、説明や答えの先出しは避ける。「2人」「1人」と数字で書く。

## 1組の形

1. 親投稿：上の粒度の1文。答えを出さず「……」で終える。
2. 子①：「実は、4/5/6つあるんです！！」の直後に**空行**を置き、①から指定数の特徴と短い理由を書く。期待だけでなく、読者が自分の状況を照らせる具体性を入れる。
3. 子②：「あなたは何個当てはまりましたか？」の直後に**空行**。当てはまる場合の希望→今連絡するか待つかは状況次第→1人で失敗したくない人への個別相談と進める。末尾は「僕と一緒に復縁を頑張りたい方は」。システムが「こちらから相談できます↓」と `https://lin.ee/sPZRcjg` を1回だけ付ける。

スマホで1ブロック最大3行、意味のまとまりで改行。公開前に `validateChain` を通す。実績、彼の本心、成功率や確実な復縁を捏造しない。拒絶やブロックを無視した接触を促さない。

## 改善サイクル

**Plan:** 直近の親投稿と各投稿の同じ経過時間の表示数を見る。1時間後を初速の主指標とし、いいね率・再投稿率は補助にする。6時間・24時間・72時間は後伸びの確認用。投稿時刻や曜日、テーマ、冒頭語、文の長さ、彼目線/2人目線、語尾を記録する。タップ率・滞在時間・LINE登録数は現行の計測値ではないので推定で埋めない。

**Do:** 勝った親投稿を「同じ文の再投稿」ではなく、**勝った構造を残した別角度の原稿**へ展開する。まず1日5枠のうち勝ち筋の近傍を複数試し、新しい方向の探索も残す。5枠すべてを無関係なテーマに分散させない。比較したい1要素以外（例：語尾を試すなら視点・テーマ・長さ）はできるだけ揃える。勝ち筋が未確定なら、彼目線と2人目線を軸に小さく試す。

**Check:** 同じ時刻帯・同じ観測窓で比較する。1時間後の表示数を第一に見るが、4.3Kなど最終表示数の勝ちと1時間初速の勝ちは分ける。同時刻の過去5件未満、観測窓不足、投稿時刻の偏りがあれば判定保留。語句・語感・視点・時間のどれが効いたかは**仮説**として扱い、1投稿で原因を確定しない。24時間で伸びたものも別の勝ちパターン候補にする。

**Act:** 各候補に「元投稿／同じ条件の比較対象／変えた1要素／1h・6h・24hの数値／解釈の確度／次に残すもの・変えるもの」を残す。再現して強い型は続け、弱い変種は戻す。翌日の生成指示には勝ち型の**実際の親投稿と数値**、次の1要素テストを渡す。分析報告は「観測事実」「原因の仮説」「次の検証」を分ける。

認知・会話型を追加する場合は、3部構成の中で言葉だけ変えて済ませない。**投稿形式**（3部解説／一言の本音／読者への問い／意外な見方／具体的な日常場面）と**画像の有無**を別々に記録する。表示数に加え、いいね率・返信率・再投稿率・プロフィール訪問・フォローを追う。相談導線は計測できる場合だけ別指標として扱い、認知投稿が初日から直接相談を生むかどうかだけで評価しない。

例：『男性が別れた彼女との復縁を考え始める瞬間って……』が後伸びしたなら、「彼目線＋復縁を考える転機＋未完」を固定し、「考え始める瞬間」対「もう一度会いたくなる瞬間」など1要素ずつ試す。投稿時刻の効果は同じフック型を複数時刻で試してから判断する。

## 出力時の確認

原稿では親・子①・子②を1組として確認する。分析では数値の時点、比較対象、仮説、次の1要素テストを明記する。ユーザーに「伸びる」と断言する前に、同じ経過時間の比較と再現テストの有無を伝える。
